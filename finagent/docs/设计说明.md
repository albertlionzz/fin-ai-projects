# finagent 设计说明

## 一、这个项目要解决什么

把两期（或多期）财务报表放在一起，人工找异常是可行的，但有两个问题：

1. **不可复算**。同一个人隔一周看同一份报表，关注的点可能不一样；换一个人结论又不同。
2. **不可追溯**。结论是"感觉应收增长不太对"，但"不太对"的边界在哪，说不清。

finagent 的做法是把"什么算异常"写成代码：阈值集中在 `RuleBook`，
每条规则有编号、有依据、有严重度。**同一个输入必然得到同一份命中清单。**

这让三件事成为可能：

- 结论可以被质疑——「为什么判定为重大？」→「剪刀差 56.3pct，超过重大线 40pct」
- 规则可以被回测——改了阈值，跑评测集就知道召回率和误报率怎么变
- 流程可以被审计——执行轨迹记录了每条规则的耗时与结果

## 二、三 Agent 的职责边界

| Agent | 输入 | 输出 | 是否用 LLM | 为什么 |
|---|---|---|---|---|
| `ExtractAgent` | 报表文本 / JSON | `FinancialStatement` | 条件使用 | 结构化是确定性任务，正则足够；仅在科目识别不足 8 个时才请模型补充 |
| `AuditAgent` | 两期 `FinancialStatement`（+ 可选 `StatementSeries`） | `Finding[]` | **绝不使用** | 判定必须可复算。这是整个系统的可信度基础 |
| `ReportAgent` | `Finding[]` | 摘要 + 研判 | 优先使用 | 措辞与归因可以容忍波动；输入被限定为已确认发现，模型无法发明异常 |

关键约束：**LLM 的输入只有 findings，没有原始报表。**
即使模型完全失控，它也只能在已确认的事实上胡说，不能凭空创造一条不存在的异常。

`AuditAgent` 的第三个参数 `series` 是后加的，但**没有破坏"绝不使用 LLM"这条边界**——
多期趋势判定同样是纯规则：序列规则 `QUALITY_DRIFT` 与持续性升级都由确定性逻辑完成，
模型连看见序列的机会都没有。

## 三、为什么严重度只有三档

`Level` 用 `IntEnum` 定义了 INFO / WARN / HIGH 三档。

不设更多档位，是因为**档位的意义在于对应动作**：
- 重大 → 需要专项核查（函证、走访、调原始凭证）
- 关注 → 需要解释（向管理层问询）
- 提示 → 记录备查

再加"中高""次高"之类，动作上无法区分，只会增加判断负担。
**分级的粒度应该由可执行动作的数量决定，而不是由感觉上需要多少档决定。**

## 四、风险分的数学选择

线性累加的问题在 README 里详述了，这里补一个更本质的说明：

我们真正需要的性质是「**边际递减但仍单调**」：
- 从 0 项重大到 1 项，风险感知应该有巨大跃升
- 从 9 项到 10 项，跃升应该很小（已经知道问题很严重了）

这正是饱和函数 `1 - e^(-x/k)` 的形状。它在 0 附近斜率最大，
随 x 增大逐渐趋平但永不为 0。

线性累加 + 封顶则完全相反：在接近上限时斜率为 0（信息全丢），
达到上限后完全无区分度。**这是选它做评分函数的唯一理由，不是为了形式好看。**

## 五、评测集的设计

`测试` 里有一组 `EXPECTED_RULES_2025A`，是人工标注的 gold 集合：

```python
EXPECTED_RULES_2025A = {"AR_GAP", "INV_GAP", "OCF_DIVERGE", "DEBT_RATIO",
                        "GOODWILL", "MARGIN_EROSION", "SWING_SCAN"}
```

示例数据里刻意植入了这 7 类异常，测试断言规则引擎必须全部命中。

这和项目一的 `eval_set.json` 是同一个思路：**没有标注集，"我改了规则"就无法量化。**
改完阈值跑一遍，是漏报多了还是误报多了，一眼可见。

另外补了两个反向测试：
- `test_clean_statements_produce_no_findings` —— 健康数据不能报出重大异常（防误报）
- `test_not_triggered_when_receivable_falls` —— 应收下降是好事，不能因为营收也降就误报

**只测"该报的报了"是不够的，还要测"不该报的没报"。** 后者更容易被忽略。

多期趋势这块把反向测试放在了更重的位置，因为新增逻辑的失效模式几乎全是误报：
- `test_flat_series_does_not_fire` —— 四期持平不能算同向恶化（`>= 0` 写成 `> 0` 的原因）
- `test_interrupted_signal_does_not_escalate` —— 中断一期不算持续
- `test_two_periods_skips_trend_entirely` —— 两期输入必须完全退化，不能产出半截趋势结论
- `test_no_escalation_without_series` —— 不传序列时，输出与改造前逐字一致

最后一条是向后兼容的底线：`RuleEngine.run()` 的 `series` 参数默认 `None`，
老调用方（CLI 两期模式、batch 模式、所有既有测试）不需要改一行代码。

## 六、多期趋势：为什么升级原有发现而不是新增一条

需求原话：

> 「连续三年应收增速超营收 20pct」比「今年突然超一次」更值得警惕

这句话拆开是两件事：**判定**（跨期反复命中）和**响应**（更值得警惕该落在哪）。

### 响应落在"升级"，不落在"新增"

直觉做法是命中持续信号时再报一条 Finding。实测有两个后果：

1. **风险分双算**。同一个应收问题，单期一次 + 持续性一次，`risk_score` 里被加两遍。
   饱和函数虽然不触顶，但它会把"一个问题"计成"两个问题"——排序直接失真。
2. **报告里同一问题出现两次**。读者会以为是两个独立问题，核查顺序被打乱，
   而且新增的那条 detail 只能复述一遍已知信息，篇幅上去了信息量为零。

所以实现是**在原 Finding 上做原地升级**：

```python
f.level = _escalate(f.level)                        # WARN → HIGH，HIGH 不越界
f.detail += "该信号在 2023A→2025A 连续 2 个报告期重复出现，非孤立波动，已升级为重大。"
f.basis += "；跨期持续性信号比单期跳变更能说明问题是结构性的"
f.confidence = min(1.0, f.confidence + 0.1)         # 有界递增
```

升级在单轮内是**有界**的：`level` 最高到 HIGH，`detail` 里持续性说明只追加一次
（不是每个命中的配对追加一遍）。测试 `test_escalation_is_idempotent_on_level`
断言 `detail.count("重复出现") == 1` 且 level 不越界。
`_escalate()` 到 HIGH 就停——持续性只能把"关注"提升到"重大"，
不造第四个档位，因为档位的意义在于对应动作（见第三节），动作无法区分就没有必要分档。

### "连续"不是"累计"

判定要求最近 `persistence_min_pairs` 个**相邻**期配对全部触发：

- 坏、坏、坏 → 持续，升级
- 坏、好、坏 → 中断一期，不升级（这是波动，不是趋势）
- 坏、坏、好、坏 → 只看最近两个配对，前两个不计

中间中断一期不计入，因为**"一次坏、一次好、一次坏"描述的是波动性，
波动性和结构性问题需要完全不同的核查动作**。把两者混为一谈会让"持续"这个词失去信息量。

这个"看几对"的参数曾经是从启用门槛推导的（`trend_min_periods - 1`），
一个参数承载两个语义的代价在真实使用里才暴露：想把持续性收紧到 3 对
（"连续三年"），就不得不把 `trend_min_periods` 调到 4，连带把
**启用门槛**也从 3 期抬到 4 期——只有 3 期数据的公司连趋势规则都跑不上了。
现在拆成两个参数（`trend_min_periods` 管"数据够不够做趋势分析"，
`persistence_min_pairs` 管"复发几次算结构性问题"），默认 3/2 与拆分前
逐字等价，`test_stricter_persistence_does_not_raise_enable_gate`
钉住解耦性质。

### 序列规则与两期规则必须分开

`QUALITY_DRIFT` 的输入是整个 `series` 而不是一对 `(cur, prev)`。
如果把它塞进两期规则的签名里，就只能拿到最后一对，看不出趋势。
但两种规则的运行条件不同：序列规则需要 ≥3 期，两期规则永远可跑。

用 `is_series_rule` 标记区分，`RuleEngine.run()` 据此分派：

```python
if rule.is_series_rule:
    if series is None or not series.has_trend(self.book.trend_min_periods):
        continue                      # 序列不足，静默跳过
    f = rule(series, self.book)
else:
    f = rule(cur, prev, self.book)
```

**静默跳过是有意的**：传 2 期数据时，整个系统退化成一个纯两期分析，
行为与加这个功能之前逐字节一致。这是向后兼容，也是测试
`test_two_periods_skips_trend_entirely` 与 `test_series_analysis_is_deterministic`
要守住的东西。

### 单期阈值法的系统性盲区

`QUALITY_DRIFT` 存在的理由是补一个盲区：**每期小幅恶化，每期都够不上观察线。**

长恒电子 fixture 就是照这个设计的——毛利率 29.00% → 27.98% → 26.67% → 25.00%，
每期变动都在 1.3pct 上下，够不上 `GROSS_MARGIN` 的 5pct 关注线。
两期模式下这套数据只能报出 1 项关注（净利率降 1.22pct，够不上 `MARGIN_EROSION` 的 2pct 重大线）。
但四期连起来看，
5 项盈利质量指标全部同向走坏，这是明确的恶化通道。

它的判定不是"所有指标都变坏"，而是**每项指标逐期检查、按重要性加权求和**：

```python
deltas = [(vals[i + 1] - vals[i]) * direction for i in range(len(vals) - 1)]
if all(d > 0 for d in deltas):        # 严格大于 0，持平不算恶化
    worsening.append((name, weights[name]))
score = sum(w for _name, w in worsening)
if len(worsening) < 2 or score < rb.quality_drift_min_score:
    return None
```

这里踩过一次坑：初版写成 `>= 0`，结果**四期完全相同的数据也触发规则**——
持平被算成"朝恶化方向走"，纯噪声数据报出重大异常。
改成严格 `> 0` 后测试 `test_flat_series_does_not_fire` 钉住。
边界条件写松一格，误报就多一类，这是规则类代码的常态。

#### 加权依据：等权计数的隐含假设不成立（第十四节）

初版是 5 项等权计数（`trend_min_agree`：≥3 项同向即触发）。等权的隐含假设是
"五项一样重要"，实测思维下这不成立：

- "经营现金流 + 杠杆 + 流动性"三项齐坏（得分 4）与"毛利率 + 净利率"两项齐坏
  （得分 5）曾被判成同一严重度，而后者明明是更强的信号；
- 反过来，两个盈利维度连续同向走坏够不着 3 项门槛，反而不报。

现行权重（`quality_drift_weights`，理由见第十四节）：毛利率 3 > 净利率 2 =
经营现金流/净利润 2 > 资产负债率 1 = 流动比率 1，门槛 5。
另保留一条**结构性底线**：至少 2 项同向——单项指标再重也可能是定价策略
调整等单一因素，跨指标 corroboration 才是这条规则的存在理由。

## 七、行业基准：阈值该跟谁比

### 问题：全市场统一线必然同时误报和漏报

`AR_GAP` 的 20pct 观察线对软件开发明显太松（该行业应收增速中位数只有 2pct），
对建筑施工又太紧（中位数 18pct，p75 已经 26pct）。
同一条线用在整个市场上，**一部分公司的正常经营会被判成异常，
另一部分公司的真实问题会被放过**。

### 实现：区间判定，两条线各自 grounded

`_industry_line()` 的规则（**重大线的取法在第十三节被真实数据推翻并重写**，
这里记的是当前版本）：

1. **无基准簿 / 行业不在表里 / 同行样本不足 5 家 → 原样返回绝对线**。
   这是向后兼容底线，也是**不能让参照数据成为单点故障**。
2. **关注线取 p75，重大线取 p90**，两端都 grounded 在同行分布上：
   p75 = "比四分之三的同行更极端，需要解释"；
   p90 = "行业最差十分之一，需要专项核查"。
   p90 缺失时（老簿子只存了 p75）重大线退回 `abs_high / abs_warn` 比例推导。
   最初的版本只校准关注线、重大线按比例拍倍数，在真实数据上两个方向都错
   （紧凑分布放过尾部、重尾分布误伤中腰，实测 22 处翻转 11:11 对称），
   完整论证见第十三节。
3. **必须分别披露两条线的来源，并写进 `Finding.evidence`**。
   `line_source` 记关注线来源（`industry:p75`），`line_high_source` 记重大线来源
   （`industry:p90` 或退回时的 `industry:p75x2.00`）——读者看到"观察线 12pct"时，
   必须能回答"这个 12 是哪来的、重大线 20 又是哪来的"。
   报告正文里另外做一层人类可读翻译，且**必须带上整条区间**
   （`已按工程机械行业分位校准（中位 6.0，p75 12.0，p90 20.0）`）：
   单说"超过 p75"会被读成"绝对偏高"，而按定义约 25% 的公司在线上方，
   那是行业常态不是异常——中位数才是"常态"的锚点。

### 校准是双向的

直觉上会把行业校准理解成"提高灵敏度"。实际上它同样在**压制误报**：
`test_calibration_can_suppress_a_finding` 构造了一个建筑施工公司
（该行业剪刀差 p75 = 26pct，比全市场线 20pct 更松），
绝对线下 gap 25pct 会报警，行业线下不报。

只测"校准后能报出更多"会漏掉这半边。**任何一个"相对化"的改动，
都要同时验证它放过了什么。**

### 样本量门槛为什么是 5

3 家同行的分位数不是基准，是噪声。门槛放在 `BenchmarkBook.get()` 一层统一执行，
而不是让每条规则各自判断——"多少家才算够"这条规则只应有一个实现。

fixture 里专门放了一个 `n_peers=3` 的「小众仪器制造」行业，
测试 `test_get_returns_none_below_min_peers` 钉住它必须被忽略。

## 八、参数敏感性：衡量档位翻转，不衡量分数变化

### 为什么不能看分数

分数是连续量。改 `scale` 从 20 到 21，分数必然变——
但档位可能一动不动，建议动作也一动不动。
**拿分数变化当敏感性指标，会得到"处处敏感"的假结论，
进而在伪精确的参数上继续手调。**

真正决定行动的是档位。所以 `scripts/sensitivity.py` 的网格衡量的是
**翻档格数 / 总格数**，输出的是稳健参数区间，不是一张分数波动表。

### ScorePolicy 为什么必须抽出来

参数如果硬编码在 `risk_score()` 方法里，做敏感性就只能另写一份公式。
那份副本会悄悄和主线逻辑漂移，跑出来的"稳健区间"是假的。

所以把 scale、三项权重、三个分数切点、两个严重度门槛
全部收进 `ScorePolicy` 一个 frozen dataclass，`DEFAULT_POLICY` 是线上行为，
任何不传参数的调用方结果不变。敏感性分析走的是**真实的 `risk_grade()`**。

### 一个反直觉的发现

35 个组合里只有 24 个在全部 4 个场景下不翻档（69%）。
但拆开看，三个真实场景稳定性都在 86% 以上，
拉低全局数字的是那个**合成边界探针**（5 项关注、分数 63.21，贴在 65 切点下方 1.79 分）——
它在 scale ≤ 15 时全部翻档。

这个探针是刻意加的：真实场景的档位多由严重度维度决定
（有重大就锁"高"），**测不出分数切点的敏感性**。
不加它，敏感性分析会给出一个虚高的稳定性数字。

### 诚实的边界

无重大异常的场景里，`w_high/w_warn` 比值根本不进入计算
（风险分只由关注项贡献），矩阵整行同值是数学必然。
报告对这类场景单独标注了这句话，**避免把"没测到"读成"很稳健"**。

## 九、审计底稿：证据，不是宣传材料

### 结论区为什么原样保留

`build_working_paper()` 刻意不改写、不润色 analysis 的原始结论：
研判文字与异常明细原样进入底稿。底稿要能被复核人、要被外部检查，
**任何"让结论更好看"的加工都会让它失去证据资格。**

### 程序区是反推的，不是模板套话

勾稽校验执行了 → 记一条"重新计算"程序；
趋势分析执行了 → 记一条"分析程序"并注明趋势区间，索引里多一条 `A-2 多期趋势分析表`；
行业校准生效了 → 记一条程序说明阈值来源。

程序区跟着实际跑过的环节走，所以两期报告的底稿和四期报告的底稿**程序数不同**——
这是应该的，底稿要反映实际做的工作。

### xlsx 为什么允许缺失

Markdown 渲染纯标准库，永远可用。xlsx 依赖 openpyxl，
`render_workpaper_xlsx()` 在缺依赖时**明确报错而不是静默降级**——
静默降级会让使用者以为拿到了表格文件，实际只拿到一半。

CLI 测试里两条路径都验证过（md 永远成功，xlsx 在无 openpyxl 时以非零码退出并说明原因）。

### 一个被测试抓出来的真实缺陷

`Procedure.to_dict()` 输出的键是 `scope`，字段名却是 `scope_`，
`from_dict()` 用 `Procedure(**p)` 还原时直接 `TypeError`——
**序列化出去的东西读不回来**。这类缺陷单看代码极难发现，
因为 to_dict 和 from_dict 各自都是"对的"，
只有 round-trip 测试能让它暴露。`test_to_dict_roundtrip` 钉住了这个约束。

## 十、A/B 框架：先定义"什么叫更好"

### 四个指标，各自防一种失效模式

| 指标 | 防的是什么 |
|---|---|
| 事实保真度 | 模型编造 findings 里不存在的数字 |
| 覆盖率 | 模型只挑顺手的说，漏掉难解释的发现 |
| 复述率 | 模型把 finding 的 detail 换个措辞重抄，没有聚合价值 |
| 可复算度 | 同一输入多次运行结果不一致 |

保真度的判定方式是从 findings **反推"允许出现的数字"集合**，
输出里每个数字都必须能在集合里找到。三个来源缺一不可：
正文数字、evidence 数值、发现计数（"重大 2 项"里的 2）。
漏掉第三类会把所有计数表述判成幻觉，误报率高到指标没法用。

### StubLLM 为什么要有 hostile 模式

`--stub hostile` 会故意往输出里注入一个 prompt 里不存在的数字（87.4%）。
跑一次必须看到它被点名抓出来——**抓不到说明指标是假的。**

框架自检只能证明"管线通、指标有区分度"（模板复述率 0%，stub 75%，对比鲜明），
**不能替代真实模型运行**。所有 `--stub` 输出在报告里都标注了这一点。

### 真实运行：覆盖率检查器被 stub 掩盖了一个 bug

2026-10-16 用本机 Ollama 的 qwen3:4b-instruct-2507-q4_K_M
（temperature 0.1，每场景 3 次）跑了第一轮真实 A/B。跑完看结果，
事实保真度全绿，**覆盖率 0%**——示例制造那一场的模型输出被判定为
"7 项发现一项都没覆盖"。

人工核对模型输出：7 项发现逐条覆盖，每个数字都有出处。
问题不在模型，在检查器。

`check_coverage` 原先只做两件事：标题原文子串匹配、规则编号匹配。
stub 的输出是照抄标题构造的，所以恒 100%；真实模型会改写措辞——
标题"5 项盈利质量指标连续 4 期同向恶化"被写成"5项盈利质量指标连续4期恶化"，
精确匹配整条判漏。**覆盖率这个指标对它的主要用户群（真实模型）恒为 0，
等于没有指标**——这与 hostile stub 要防的"指标是假的"是同一种病，
只是方向相反：假阳变成假阴。框架自检之所以没抓到，正因为 stub
天生就是"照抄标题"的输入分布。

修复走三条路径的并集（任一命中即覆盖）：

1. **忽略空白的标题匹配**：标题与输出都去掉所有空白后做子串匹配，
   专治"5 项"→"5项"这类排版级差异；
2. **规则编号**：输出含 `QUALITY_DRIFT` 等编号即算覆盖；
3. **标题独有内容**：跨标题先去重（共享的词与数字不构成证据），
   标题独有汉字的 ≥80% 出现在输出中，或标题独有指标数字命中。

第 3 条的关键是"独有"：年份（1900–2100 整数）与 10 以下整数
（计数类的"3 项""连续 4 期""权重 2"）在所有标题里反复出现，
没有区分度，作为弱数字剔除——否则任意一段提到"连续 4 期"的文字
都能把另一条标题判成已覆盖。

qwen3:4b 那份真实输出被固化成回归样本
（`_REAL_LLM_OUTPUT_07FINDINGS`，`test_real_llm_output_is_fully_covered`），
连同"丢同义词 + 去空格仍覆盖""独有数字路径""共享词不交叉覆盖"
"弱数字不作证据"共 5 条测试。修复后重跑，覆盖率回到 100%。

### 真实运行还验证了什么

| 指标 | 结果 | 读法 |
|---|---|---|
| 事实保真度 | 4/4 场景 100% | 验收线达标，但样本是本地 4B，不能外推到云端大模型 |
| 覆盖率 | 4/4 场景 100% | 修复后；修复前恒 0 |
| 复述率 | 0% | 模型没有换措辞重抄 detail，聚合章节是真聚合 |
| 可复算性 | 33%~67% | 同一输入 3 次运行，没有两次逐字节相同 |

最后一行值得单独说：**temperature 0.1 的真实模型仍然不确定。**
这不是模型的问题，是"让 LLM 产出可复算结论"这个要求本身不成立。
它实证了本项目的架构主张——判定必须交给规则引擎，
LLM 只在措辞环节介入。一个连跑两次都不一样组件，
不可能承担"同一个输入必须得到同一个结论"的第一要求。

A/B 产物现在带出处块（模型、端点、temperature、每场景运行次数），
没有出处的 A/B 报告不可复算，等于没有报告。

## 十二、真实数据源：基准从模拟走到抓取

第七节落地时基准是 5 个行业 × 4 项指标的**构造值**——它能证明校准机制
本身成立，但证明不了"阈值跟真实同行比是对的"。这一节记的是换成真实数据
过程中踩到的四个问题，每一个都不是"抓下来就行了"。

### 站点没有 API 可用时的取证顺序

auditdog.cn 是 Next.js App Router 应用，页面数据以内嵌 RSC payload
（`self.__next_f.push([1,"..."])`）的形式下发，没有 REST 接口可调。
可用的取证路径只有一条：**从 HTML 里反推行 ID 与数值单元格的结构**。

关键发现是**同一张表有两种精度的值**：主表是"20.45 亿"式 2 位小数
（大额科目够用，小基数科目的增速会被四舍五入毁掉），而附注区偶尔
给出全精度（`87,407,775.73`）。这个精度差异直接决定了可行性——
如果只有主表精度，`ar_growth_gap` 这类小基数指标的基准就不能用。
实测下来 111 家里只有极少数科目落在低精度区间，可接受，但必须记账。

### 一家公司 4 次请求，不是 2 次

直觉上"当期 + 上期"是 2 次请求。实际是 4 次：资产负债表与利润表各一张，
每张都要 2025AR / 2024AR 两期——**页面只渲染单期单值，没有上年同期列**。
附注区也没有期初余额列。所以"能不能少抓一半"这个优化不存在，
除非换数据源。

顺带一个反例：`/api/public/indicators/compare` 是个真 API，返回同行
原始值，看上去能直接算分位数。但它的 21 项核查指标与 finagent 的 4 项
基准指标**完全不重合**。可用的公开接口不等于可用的数据。

### 材料性门槛该定在哪：一次没有为了好看而做的决定

增长类指标（`ar_growth_gap`）的分布会被小基数公司污染：兰州河基期应收
143 万、占营收 0.66%，一年增了 1733%，把 p90/p95 打到 74/144。
爬虫里原本有一道门槛——基期科目 < 基期营收 0.1% 不计入分布。

离线重算发现，把门槛抬到 0.5% 或 1.0%，p75 会从 23.63 降到 18.04。
**数字会好看很多**（更"合理"的阈值、更少触发）。但没有这么做：

- 0.1% 门槛的**设计意图**是排除"基期近乎不存在"的科目
  （山西汾酒基期应收 7.5 万、占营收 0.000%，酒鬼酒 1.3 万）
- 兰州河 0.66% 按这个定义**应当保留**——它是真实的小基数，不是脏数据
- 为了压低阈值而抬高门槛，是用排除数据的方式伪造结论

最后的选择是**保留门槛、记录后果**：README 的已知局限里写明
"p75 有约 5pct 的门槛不确定性"，并给出三种门槛下的重算结果。
这是把不确定性交给读者，而不是藏进参数里。

### 一个必须讲清楚的语义变化

用 p75 当观察线，按定义任一行约 25% 的公司会落在线上方。
食品饮料 111 家实测：**44 家公司的触发项因校准而改变**
（41 家变多、3 家变少），51 处单项判定翻转，绝大多数集中在
`debt_ratio`（绝对线 70% 对食品饮料过松）和 `gross_margin_delta`
（绝对线 5pct 过松）。

这不只是"灵敏度变了"。**"关注"的含义从"绝对偏高"变成了
"处于同行业最差四分之一"**。前者是绝对的，后者是相对的——
如果报告读者仍按前一种理解，会把一个行业的正常分布
（25% 的公司在线上方）读成"普遍恶化"。

所以端到端验证特意挑了**两个方向**各一家公司：

| 公司 | 绝对线 | 行业校准 |
|---|---|---|
| 伊利股份 | 0 项，风险分 0.0 [低] | 1 项重大，39.3 [高]（行业线更严） |
| 青岛啤酒 | 1 项关注，18.1 [中] | 0 项，0.0 [低]（行业线更松） |

两个方向都跑通，才敢说校准机制在真实数据上是双向起作用的，
而不只是在模拟 fixture 里自证。

### 被测公司与基准必须同源

`scripts/build_fixture_from_raw.py` 把爬虫缓存还原成 finagent 的
statement JSON。这一步看起来多余，实际防的是一个隐蔽的失效：

如果基准来自 auditdog 的 AI 抽取、而被测公司来自另一套口径
（比如手抄 Wind 数据），那么"行业校准"这个动作本身就不成立——
两条数据链的误差结构不同，比较结果没有意义。

桥接脚本的测试钉住一条耦合不变量：**模型与规则读到的每个科目，
映射表都必须能产出**。规则将来新增一个科目消费而映射表没跟上时，
那条规则会永远不触发，而且不报错、报告里也看不出来。

## 十三、区间判定：比例线为什么必须换成 p90

第十二节落地后的第一版校准有个当时没看出来的问题：**关注线换了行业分位，
重大线却还在按比例拍**。`_industry_line()` 里 `high = warn × (abs_high / abs_warn)`，
四舍五入就是"重大 = 2 × 关注"。这个写法在模拟 fixture 上看不出毛病——
构造数据里 p90 恰好都约等于 p75 的 1.7 倍，比例线歪打正着。

真实数据一跑就两个方向都错。食品饮料 111 家：

| 指标 | p75 | 比例重大线 | 实测 p90 | 比例线的实际后果 |
|---|---|---|---|---|
| `ar_growth_gap` | 23.63 | 47.26 | 73.27 | 把 16 家判成重大，而最差十分之一只有 8 家 |
| `inv_growth_gap` | 21.53 | 43.06 | 35.34 | 行业尾部拿不到重大，只拿到关注 |
| `gross_margin_delta` | 2.86 | 5.72 | 4.42 | 同上，5 家尾部被降级 |
| `debt_ratio` | 46.83 | 53.52 | 56.52 | 同上，4 家被降级 |

换成 p90 后重跑，115 项校准发现里 **22 处判定翻转，11:11 对称**。
这个对称是这次改造最有价值的发现：它证明比例线的问题不是"偏松"或"偏严"，
而是**它与分布形状无关**。同一个 2 倍倍数，在紧凑分布上放过尾部、
在重尾分布上误伤中腰，换个行业就换个错法——而错的方向你事先无法预判。

### 区间披露：从"一根线"到"一条带"

比换阈值更重要的是**披露方式**。原来的 detail 只说"观察线 24pct；
已按工程机械行业 p75 分位校准"，读者看到的是一个孤零零的数字。
单看这个数字，"超过观察线"会被理解成"绝对偏高"——而按定义，
任一行约 25% 的公司在线上方，**这是行业常态不是异常**。

现在 detail 给整条区间：

> 资产负债率 61.51%（观察线 47%；已按食品饮料行业分位校准（中位 35.1，p75 46.8，p90 56.5））

中位数是"常态"的锚点。有了它，读者能自己定位这家公司在行业区间的哪个位置，
而不是只剩一个来源不明的阈值。`evidence` 里同步增加三个机器可读字段：
`line_high_source`（`industry:p90` 或退回时的 `industry:p75x2.00`）、
`industry_p50`、`industry_p90`——**两条线各自可披露**，
复核人要能分别回答"关注线哪来的、重大线哪来的"。

### 这次改造的代价

p90 在重尾指标上不稳，这条必须记账。食品饮料 `ar_growth_gap`
过滤后样本里兰州河（基期应收占营收 0.66%，按材料性门槛定义**应当**保留，
见第十二节）剪刀差 1733pct。离线敏感性：

- 完整样本（n=103）：p90 = 73.27
- 去掉最大 1 个值（n=102）：p90 = 64.90
- 去掉最大 3 个值（n=100）：p90 = 52.77

也就是说该行业该指标的重大线有约 ±20pct 的带宽，8 处 `HIGH→WARN`
翻转里有一部分落在这个带宽内，不是干净的结构性结论。
紧凑分布的指标（`inv_growth_gap`、`gross_margin_delta`）不受此影响，
它们的 p90 由样本中腰部决定。

**没有为了稳定性去动口径**（比如换 trimmed p90 或 p87.5）——
那会引入第二个需要解释的参数，而"最差十分之一"是读者能直接理解的语义。
选择是保留 p90、把带宽写进已知局限 12。

## 十四、盈利质量指标的重要性权重

`QUALITY_DRIFT` 初版把 5 项指标等权计数：`trend_min_agree = 3`，
5 项里任意 3 项连续同向即触发重大。问题与第十三节同源——
**等权是一个未经审查的隐含假设**，而且这次错得更早：阈值还未经真实数据检验，
假设本身就不成立。

### 等权计数把两类组合判成同一严重度

| 组合 | 等权计数 | 加权得分 | 加权后 |
|---|---|---|---|
| 毛利率 + 净利率齐坏 | 2 项 < 3，**不触发** | 3 + 2 = 5 | **触发** |
| 现金流 + 杠杆 + 流动性齐坏 | 3 项 ≥ 3，触发 | 2 + 1 + 1 = 4 | 不触发 |
| 毛利率单项连降四年 | 1 项，不触发 | 3 | 不触发（结构性底线） |

第二行是等权最刺眼的一处：三个与"盈利质量"关系最远的指标凑数，
压过了两个直接的盈利维度。第一行则是等权的另一面——
最强的可用 corroboration 反而够不着门槛。

### 权重与理由

现行权重（`quality_drift_weights`）：

| 指标 | 权重 | 理由 |
|---|---|---|
| 毛利率 | 3 | 竞争地位与定价权的直接体现，盈利质量恶化的**领先指标** |
| 净利率 | 2 | 盈利的最终结果，受毛利率驱动，另含费用与非经常项信息 |
| 经营现金流/净利润 | 2 | 利润的含金量（应计质量），"纸面利润"的照妖镜 |
| 资产负债率 | 1 | 偿债安全边际，与盈利质量相距较远，只作佐证 |
| 流动比率 | 1 | 同上 |

门槛定 5：**最强两指标组合恰好达标**（两个盈利维度连续同向走坏即构成
恶化通道，不需要弱指标凑数），纯弱指标组合够不着。

另有一条**结构性底线**：至少 2 项同向才判定。这不是可调参数——
单项指标再重也不算"多项同向"，单一毛利率连降四年可能是定价策略调整，
跨指标 corroboration 才是这条规则的存在理由。权重全部设为 1、
门槛设为 3 即可逐字复现等权时代的行为（`test_equal_weights_reproduce_old_counting`
钉住这个等价性），所以新参数化是旧行为的超集，不是替换。

### 记账：量化结果与它改变了什么

权重是推理判断，但**翻转规模已经用真实数据量化过**（2026-10-16）。
对食品饮料按等距抽样 30 家补抓 2023AR 报表与三期现金流量表，重跑对比：

| 口径 | 触发数 |
|---|---|
| 旧（等权 ≥3 项） | 3 家 |
| 新（加权 ≥5 分） | 6 家 |
| **判定翻转** | **5 处（30 家的 17%）** |

四个方向完全符合加权设计的预期，没有一次是意外：

- **4 家新触发全部恰好 5 分**——毛利率 + 净利率两个盈利维度连续同向走坏
  （贵州茅台、百合股份、口子窖、良品铺子）。旧口径下三项同向才触发，
  强弱两项够不着；加权后最强组合恰好压线。
- **1 家被抑制**（桂发祥）：同向的是净利率 + 杠杆 + 流动性（加权 4 分）。
  它的净利率三年从 12.11% 崩到 −5.21%，加权趋势规则确实压掉了这条，
  但单期规则 SWING_SCAN 仍以净利润 −190.6% 抓住并升级——
  **被加权抑制 ≠ 没人管**，这条案例钉住了两层规则的配合关系。

茅台这个翻转需要交代读法：毛利率三年只降了 0.79pct（91.97→91.18）
照样触发，因为趋势规则只看方向不看幅度。这对"慢性恶化型"是特性，
但读报告的人必须知道**触发的含义是"连续同向"，不是"变化剧烈"**。

边界仍然存在：抽样 30 家、单一行业、权重本身仍未经专家标注校准
（第十一节第 8 条）。但"翻转只朝设计预期方向发生、且强弱组合的
行为差异可逐家解释"这件事，已经从推理变成了实测。

顺带做了两个冒烟实验回答"权重还要不要紧"：把权重归一到同排序、
仅调幅度（毛利率 3.15 / 净利率 2.25 / 现金流 2.25 / 杠杆 0.72 /
流动性 0.63），30 家样本的触发集合**一家不变**；换成"现金流至上"的
极端排序（毛利率 1.35 / 现金流 3.6），则 4 家毛利率+净利率公司
（含茅台）不再触发。**触发集合对"同排序内的幅度调整"稳健，
对"换排序"敏感**——所以专家标注要校准的是排序与相对量级，
不是小数点。
