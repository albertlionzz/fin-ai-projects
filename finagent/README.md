# finagent · 财务报表差异分析 Agent

> 三 Agent 分工的财务异常识别内核。
> **确定性优先，LLM 只在最后一环介入**——判异常靠规则，写结论才用模型。
> 零第三方依赖，`git clone` 后直接能跑出命中清单与风险分。

## 这是什么

不是"让 AI 读财报"的 demo，是一个**规则可复算、结论可辩护**的分析流水线。
它回答的问题是：

> 「两期财务报表摆在一起，哪些差异是真的异常，依据是什么，先查哪个？」

与项目一的关系：

| | finrag（项目一） | finagent（项目二） |
|---|---|---|
| 解决的问题 | 从制度文档里**查到条款** | 从财务数字里**发现异常** |
| 核心产物 | 带引用的答案 | 带依据的异常清单 |
| 评测方式 | recall@k / MRR / 幻觉率 | 规则召回率 / 误报率 |
| 共享约定 | 纯标准库、dataclass 驱动、可插拔 Protocol、可独立单测 | 同上 |

两个项目共用同一套工程约定。项目一的 `Embedder` Protocol 和项目二的 `LLM` Protocol
是同一个设计思路：**核心逻辑不依赖具体外部服务，接口稳定，实现可换。**

## 架构

```
两期或多期报表 JSON
   │
   ├─ ExtractAgent          科目抽取（确定性正则；科目<8 时才启用 LLM 兜底）
   │      └─ 未识别行记入 meta.unrecognized，不静默丢弃
   │
   ├─ AuditAgent            异常判定（★ 刻意不接 LLM）
   │      └─ RuleEngine.run()   10 条规则 → Finding[]
   │             ├─ 单条规则失败不中断整轮，记 ERR_<name> 后继续
   │             ├─ 传入 benchmarks 时按行业分位校准 4 条规则的观察线
   │             └─ 传入 series 时额外执行：
   │                  ├─ 序列规则（QUALITY_DRIFT 等多期同向恶化）
   │                  └─ 持续性升级（跨期反复命中的发现提升一级严重度）
   │
   ├─ ReportAgent           结论生成（★ 唯一引入 LLM 的环节）
   │      ├─ summarize()   确定性摘要
   │      └─ reason()      有 LLM 走生成；无 LLM 走确定性聚合模板
   │
   └─ Orchestrator          串成链路，任何一环失败不中断，trace 如实呈现
          │
      render.py              终端摘要 / Markdown 报告
      workpaper.py           审计底稿（Markdown + xlsx，五张表）
      benchmarks.py          行业基准簿（分位数查询 + 样本量门槛）
      abcompare.py           研判质量四维指标（保真 / 覆盖 / 复述 / 可复算）
```

### 为什么判定环节刻意不用 LLM

财务报表分析的第一要求不是"说得好听"，是**同一个输入必须得到同一个结论**。
LLM 做不到这一点。所以分工是：

- **规则引擎判"是不是异常"**——阈值写在 `RuleBook` 里，可复算、可辩护、可被审计质疑
- **LLM 只写"这意味着什么"**——输入限定为已确认的 findings，模型没有机会自己发明异常

这不是"保守"，是**把不可靠组件放在伤害最小的位置**。
一个在判定环节胡说八道的模型会让整份报告失去价值；一个在措辞环节发挥不佳的模型，
最坏结果只是文字不够漂亮，事实依然准确。

## 规则清单（11 条）

| 规则编号 | 名称 | 观察线（关注 / 重大） | 依据 |
|---|---|---|---|
| `BS_IDENTITY` | 资产负债表勾稽校验 | 容差 0.1% | 资产 = 负债 + 所有者权益 |
| `AR_GAP` | 应收增速 vs 营收增速 | 20pct / 40pct | 剪刀差是收入质量恶化先行指标 |
| `INV_GAP` | 存货增速 vs 营收增速 | 20pct / 40pct | 增速持续高于营收指向滞销 |
| `GM_SWING` | 毛利率大幅变动 | 5pct / 10pct | 异常升或降都需解释 |
| `OCF_DIVERGE` | 经营现金流 / 净利润 | 0.8 / 0.5 | 现金含量低指向纸面利润 |
| `DEBT_RATIO` | 资产负债率 | 70% / 80% | 杠杆与偿债风险基础度量 |
| `GOODWILL` | 商誉 / 净资产 | 30% / 50% | 并购减值风险敞口 |
| `MARGIN_EROSION` | 增收不增利 | 净利率降 2pct | 盈利质量恶化典型形态 |
| `NET_MARGIN_TURN` | 净利率由正转负（由盈转亏） | 转亏即报，亏损深度 5% | 转亏是盈利**性质**变化，非幅度波动 |
| `SWING_SCAN` | 科目同比大幅波动扫描 | 50% / 100% | 全面覆盖，防专项规则遗漏 |
| `QUALITY_DRIFT` | 多项盈利质量指标连续同向恶化 | 加权得分 ≥5（毛利率3/净利率2/现金流2/杠杆1/流动性1） | 单期够不上观察线、多期同向走是慢性恶化 |

`NET_MARGIN_TURN` 是实测补的缺口，不是设计时想到的：全样本 911 家 2024A→2025A
有 79 家净利率由正转负，其中 31 家没有任何专门针对盈利的规则命中——
它们只落到 `SWING_SCAN`，且**全部是重大级**（"存在 2 个科目同比大幅波动"）。
告警是有的，但读的人得自己从"净利润同比 −190%"推断出"这家转亏了"。
根因是 `MARGIN_EROSION` 前置要求营收增长，**营收下滑时的转亏（"减收更减利"）它不覆盖**，
而 `QUALITY_DRIFT` 要三期数据、净利率只值 2 分（净利率2+杠杆1+流动性1=4 < 5 会被抑制）。
补上这条后 79/79 都有专门规则命中。细节见 `docs/设计说明.md` 第十五节。

其中 `AR_GAP` / `INV_GAP` / `GM_SWING` / `DEBT_RATIO` 四条**支持行业校准**：
传入基准簿后，观察线取该行业的 p75 分位、重大线取 p90 分位而非全市场固定值
（p90 缺失时重大线才按原有比例推导）。校准结果一律写进
`Finding.evidence.line_source`——财务工具不能悄悄换阈值。

前 10 条是**两期规则**（接收 `cur, prev`）；`QUALITY_DRIFT` 是**序列规则**（接收整个 `series`），
只有传入 ≥3 期报表时才会执行。序列规则与两期规则通过 `is_series_rule` 标记区分，
`RuleEngine.run()` 据此分派，互不干扰。

全部阈值集中在 `RuleBook` 一个 dataclass 里。**改阈值不需要碰任何规则逻辑**——
这是为了让"参数该定多少"成为一个可以单独讨论、单独回测的问题。
与趋势相关的阈值同样在这里：`trend_min_periods = 3`（至少几期才算有趋势，
是趋势规则的启用门槛）、`persistence_min_pairs = 2`（最近几对相邻期全部触发
才算"持续"，是持续性升级的判定标准）、`quality_drift_weights`（5 项盈利
质量指标的重要性权重）与 `quality_drift_min_score = 5`（`QUALITY_DRIFT`
的加权得分门槛）。
前两个是拆开的：它们管的是两件不相干的事（数据够不够做趋势分析 /
复发几次算结构性问题），绑在一起会让"收紧持续性判定"顺带把
3 期数据的公司踢出趋势分析。

`QUALITY_DRIFT` 的权重也不是拍脑袋：**等权计数的隐含假设"五项一样重要"
不成立**。等权时代，"经营现金流+杠杆+流动性"三项齐坏与"毛利率+净利率"
两项齐坏被判成同一严重度；加权后前者得分 4 不触发、后者得分 5 触发。
另有一条结构性底线：至少 2 项同向才判定——单项指标再重也可能是
定价策略调整等单一因素，跨指标 corroboration 才是这条规则的存在理由。

### 多期模式实测（长恒电子，4 期，慢性恶化型）

`data/statements/长恒电子_2022A..2025A.json` 是第二套 fixture，刻意设计成
**每一期都够不上时值观察线、但连续四期构成明确恶化通道**：

| 指标 | 2022A | 2023A | 2024A | 2025A |
|---|---|---|---|---|
| 毛利率 | 29.00% | 27.98% | 26.67% | 25.00% |
| 净利率 | 8.60% | — | 6.76% | 5.54% |
| 资产负债率 | 50.00% | — | — | 57.27% |
| 经营现金流/净利润 | 1.14 | — | — | 0.82 |
| 流动比率 | 1.73 | — | — | 1.36 |

两期模式下这套数据**只能报出 1 项关注**（`MARGIN_EROSION`，净利率降 1.22pct，
够不上 2pct 重大线）——净利率三年从 8.60% 掉到 5.54% 这件事，
在两期视角里只是一个轻飘飘的"关注"。
切到 4 期模式：

```
风险分 63.2/100 [高]    重大 2  关注 0   合计 2

🔴 MARGIN_EROSION  净利率 6.76% → 5.54%（-1.22pct）
                   该信号在 2023A→2025A 连续 2 个报告期重复出现，
                   非孤立波动，已升级为重大
🔴 QUALITY_DRIFT   毛利率、净利率、经营现金流/净利润、资产负债率、流动比率
                   在 2022A→2025A 期间持续走坏，每一期都朝同一方向变动
```

注意 `MARGIN_EROSION` 那条：**它不是新增的发现，是原有发现被升级了。**
单期只看 2025A 时它是"关注"级（净利率降 1.22pct，够不上 2pct 重大线）；
但它在 2023A→2024A、2024A→2025A 两个相邻配对都触发，说明是结构性的，
于是升级为重大并在 detail 里追加持续性说明。**报告里同一个问题只出现一次，
风险分也不会双算。**

### 怎么读这个分数（面试会问的三个问题）

**Q：92.6 是怎么算出来的？为什么不是把异常数量加权求和？**

第一版就是加权求和，然后发现它有个致命缺陷：
4 项重大 = 4×10 = 40，8 项重大 = 80，一旦超过 10 分就 `min(100)` 封顶。
结果 **"4 项重大"和"8 项重大"拿到同样的 100 分**，分数完全失去区分度。

改成饱和函数 `(1 - e^(-raw/20)) × 100`：单调递增，永不触顶。

| 重大项数 | 修前 | 修后 |
|---|---|---|
| 4 | 100.00 | 86.47 |
| 8 | 100.00 | 98.17 |
| 差值 | **0.00** | **11.70** |

这个缺陷是我自己跑数据时发现的——**没有意识到"封顶"是一个 bug 的人，
不会去做这个对比表。** 评分函数必须保留边际区分能力，这是排序问题的基本要求。

**Q：scale=20 这个参数凭什么？**

老实说：**这是经验值，不是调优结果。** 当前权重下约 3 项重大 + 2 项关注能到 70 分区间，
符合直觉上"相当不妙但不至于灾难"的定位。它应该随历史样本回测校准。
在没有样本之前，任何精确到小数点的加权都是伪精确——**所以我把它写成常量并标注了这一点，
而不是假装它是经过验证的。**

**Q：为什么要有风险等级，不能只给分数吗？**

分数是标量，读者需要的是"该做什么"。所以每个分数映射到档位并附带建议动作：

| 分数 | 等级 | 建议动作 |
|---|---|---|
| ≥85 | 极高 | 暂缓出具结论，先逐项核查重大异常原始凭证 |
| ≥65 | 高 | 对重大异常做专项函证或走访核实后再定稿 |
| ≥35 | 中 | 就关注项向管理层提出书面问询 |
| <35 | 低 | 未见系统性异常，可常规复核 |

**Q：分数和严重度打架时听谁的？**

听严重度的。`risk_grade()` 取「分数档」与「严重度档」的较高者，
且**存在 1 项重大，档位就不得低于「高」**。

这条规则是修 bug 修出来的：4 期分析跑出"重大 2 项、关注 0 项、风险分 63.2"，
档位却落在「中」，建议动作是"就关注项向管理层提出书面问询"——
**一份报告告诉读者"去问那 0 项关注"，这是自相矛盾。**
饱和函数在重大项少时得分天然偏低（3 项重大约 70 分），
纯按分数切档会把"数量少但性质严重"的情况漏掉。

测试 `test_grade_never_contradicts_severity` 钉住了这个约束：
`by_score` 与 `by_severity` 取较高者，档位永远不会低于严重度所要求的水平。

### 行业校准实测（恒润重工，同一份数据两种口径）

`data/statements/恒润重工_2025A.json` 是第三套 fixture，`meta.industry = 工程机械`，
刻意设计成**全市场口径零异常、同行业口径两项进最差四分之一**：

| 指标 | 实测值 | 绝对线 | 工程机械 p75 |
|---|---|---|---|
| 应收剪刀差 | 15.0pct | 20（不触发） | **12（触发）** |
| 资产负债率 | 62.0% | 70（不触发） | **60（触发）** |

不传基准簿时输出"未触发任何异常规则"；传入后输出 2 项关注，
detail 里明确写出 `已按工程机械行业分位校准（中位 6.0，p75 12.0，p90 20.0）`，
`evidence.line_source` 记录机器可读的 `industry:p75`、
`line_high_source` 记录 `industry:p90`。两项都在 p75 与 p90 之间，
所以是关注级而非重大级——区间判定的意义就在这里：
同一个 15pct 的剪刀差，落在 [12, 20) 是"需要解释"，
超过 20 才是"需要专项核查"。

反向也同样成立——测试 `test_calibration_can_suppress_a_finding` 构造了一个
建筑施工公司（该行业剪刀差 p75 = 26pct，比全市场线还松），
绝对线下 gap 25pct 会报警，行业线下不报。**校准是双向的，
不是只用来提高灵敏度。**

### 参数敏感性实测（35 个组合，69% 稳健）

`scripts/sensitivity.py` 对 scale 与权重比跑网格，衡量指标是**档位是否翻转**，
不是分数变化——分数是连续量，改任何参数它都会变；
真正决定行动的是档位（极高=暂缓出具结论、高=专项函证、中=书面问询、低=常规复核）。

结果（`artifacts/sensitivity.md`）：

| 场景 | 基准档位 | 翻档格数 | 稳定性 |
|---|---|---|---|
| 示例制造（重大 4 / 关注 3） | 极高 | 0/35 | 100% |
| 长恒电子（重大 2 / 关注 0） | 高 | 5/35 | 86% |
| 恒润重工（关注 2，行业校准） | 中 | 0/35 | 100% |
| 合成边界（5 项关注贴 65 切点） | 中 | 10/35 | 71% |

全局 24/35 个组合在全部场景下不翻档，**默认参数（scale=20、比值 2.5）位于稳健区间内**。
合成边界那一行是最有信息量的：它在 scale ≤15 时全部翻档，说明
"分数恰好落在切点附近"的结论本就该被视为不稳健——
这正是不做敏感性分析就永远发现不了的事。

顺带一个诚实的注脚：无重大异常的场景里，`w_high/w_warn` 比值根本不进入计算
（风险分只由关注项贡献），矩阵整行同值是数学必然，不是稳定性证据。
报告里对这类场景单独标注了这一点，避免把"没测到"读成"很稳健"。

### 行业基准接真实数据（auditdog.cn 三大报表）

`data/benchmarks/industry_benchmarks.json` 是**模拟 fixture**，测试钉在它的具体数值上
（工程机械 `ar_growth_gap` p75=12.0、小众仪器制造 `n_peers=3` 触发样本量门槛），
所以它不能被真实数据覆盖。真实数据由 `scripts/fetch_benchmarks.py` 抓到另一个文件：

```bash
# 干跑：只枚举公司清单，零报表请求
python scripts/fetch_benchmarks.py --industries 食品饮料 --dry-run

# 抓一个行业全量（食品饮料 111 家 × 4 请求 = 444 次，实测 1301 秒）
python scripts/fetch_benchmarks.py --industries 食品饮料 --delay 1.0

# 用时直接指过去
python scripts/run.py analyze --cur X_2025A.json --prev X_2024A.json \
                              --benchmarks data/benchmarks/industry_benchmarks.auditdog.json
```

数据源是 bbs.auditdog.cn 的三大报表 Beta（站点自上市公司公开年报 AI 抽取）。
一家公司要 4 次请求：资产负债表与利润表各取 2025AR / 2024AR 两期
（页面只显示单期单值，没有上年同期列）。全行业按 `/data` 分页枚举，
每页 50 家，按 ROE 降序。

**四个必须交代的口径问题**，每一个都可能让基准悄悄失真：

1. **`gross_margin_delta` 取绝对值**。规则里比的是 `abs(delta)`，
   所以基准必须是**绝对变动**的分布。直接拿带符号值算 p75 会得到 +0.8 这种
   单侧阈值——于是一半公司的负向大幅波动会被判成"正常"。
2. **增长类指标设材料性门槛**：基期科目 < 基期营收的 0.1% 时不计入分布。
   否则"应收从 10 万到 500 万"会把 p90/p95 打成噪声。
3. **默认排除 ST 公司**（食品饮料 122 家里有 11 家，电子 495 家里有 10 家）。
   退市风险与重组会让财务分布失真；排除名单写进构建报告
   （`excluded_st` 字段），`--include-st` 可以关掉这个过滤。
   *踩坑记录*：ST 过滤发生在 `crawl_industry` 之前，统计函数看到的已是
   过滤后清单，`excluded_st` 一度恒为空列表——"默认排除"这件事在报告里
   无据可查。已改为回到枚举全量取名单，并有单测钉住（`test_st_exclusion_list_is_recorded`）。
4. **行业级 `n_peers` 取保留指标的最小值**（最弱环节口径）。银行没有应收和存货，
   按指标分别记同行数会更精确，但基准簿的序列化格式只有一个行业级 `n_peers`，
   各指标自己的同行数记在 `build_report.json` 里。

#### 食品饮料实测（111 家，444 次请求，1301 秒）

| 指标 | n | p50 | p75 | p90 | p95 | min / max |
|---|---|---|---|---|---|---|
| `ar_growth_gap` | 103 | −2.53 | **23.63** | 73.27 | 142.44 | −91.68 / 1733.58 |
| `inv_growth_gap` | 111 | 8.15 | **21.53** | 35.34 | 45.09 | −70.28 / 113.05 |
| `debt_ratio` | 111 | 35.06 | **46.83** | 56.52 | 63.12 | 4.14 / 86.33 |
| `gross_margin_delta` | 111 | 1.33 | **2.86** | 4.42 | 5.79 | 0.05 / 14.44 |

`ar_growth_gap` 少 8 家是材料性门槛挡掉的（山西汾酒基期应收 7.5 万、
酒鬼酒 1.3 万，占营收 0.001% 以下——这种基期的增速没有经济意义）。

**两层校验**：每家公司用 `/data` 概览列（营收、总资产）与报表解析值交叉比对，
偏差超 1% 记告警；产出文件必须通过 `load_benchmarks()` 加载成功才算完成。
111 家里 1 家告警：贵州茅台营收偏差 1.87%——它有集团财务公司，
`营业总收入` 含利息收入而利润表 `营业收入` 不含，是**列口径差异不是抓取错误**
（全行业中位偏差 0.000%，另外 110 家全部 <0.31%）。

**已知局限（必须连着读）**：`ar_growth_gap` 的 p90/p95 被小基数公司推高
（兰州河基期应收 143 万、占营收 0.66%，剪刀差冲到 1733pct）。材料性门槛
按"基期是否近乎不存在"设计，这家按定义应当保留，所以没有为了数字好看而抬高门槛。
离线重算三种门槛的后果：0.1% → p75=23.63；0.5% 与 1.0% → p75=18.04。
** operative 的 p75 因此有约 5pct 的门槛不确定性**，用的时候要知道这一点。
另外主表数值是「1.27 亿」式 2 位小数，小基数科目的增速精度约 ±0.5pct。

#### 电子行业实测（485 家，排除 ST 10 家，5534 秒）

| 指标 | n | p50 | p75 | p90 | p95 |
|---|---|---|---|---|---|
| `ar_growth_gap` | 485 | −3.67 | 10.10 | 29.73 | 72.96 |
| `inv_growth_gap` | 485 | −0.10 | 14.82 | 37.52 | 54.18 |
| `debt_ratio` | 485 | 35.87 | 51.74 | 65.16 | 73.66 |
| `gross_margin_delta` | 485 | 1.97 | 3.95 | 6.66 | 9.31 |

与食品饮料的对照恰好示范了"为什么绝对线不可跨行业用"：
电子行业 `debt_ratio` 的 p75（51.7）比食品饮料（46.8）高约 5pct，
`gross_margin_delta` 的 p50（1.97）是食品饮料（1.33）的 1.5 倍——
制造业的杠杆与毛利率波动本就是不同的常态。

两个行业口径差异的实测：**材料性门槛在电子行业几乎无影响**
（485 家里排除 0 家，食品饮料排除 8 家）——电子公司基期应收/存货
小到可以忽略的比例远低于食品饮料。另外电子首跑有 4 家遇到源站
瞬时故障（HTTP 521/522，不是数据问题），缓存续跑自动恢复，
重建后 `parse_errors` 归零。

#### 计算机行业实测（315 家，排除 ST 19 家，67967 秒）

| 指标 | n | p50 | p75 | p90 | p95 |
|---|---|---|---|---|---|
| `ar_growth_gap` | 315 | −1.67 | 9.54 | 23.58 | 40.93 |
| `inv_growth_gap` | 305 | 3.82 | 28.94 | 71.99 | 115.08 |
| `debt_ratio` | 315 | 32.63 | 47.66 | 60.92 | 70.56 |
| `gross_margin_delta` | 315 | 2.85 | 5.29 | 9.25 | 14.14 |

第三个行业把"绝对线不可跨行业用"又推深了一层：计算机
`debt_ratio` 的 p75（47.7）比食品饮料（46.8）只高 0.9pct，
但 `gross_margin_delta` 的 p90（9.25）是食品饮料（4.42）的 2.1 倍——
**杠杆水平三个行业趋同，盈利波动率却差一倍**。同一个"行业校准"
覆盖的指标里，有的跨行业稳定、有的一倍差距，不存在"调一次参数
通用所有指标"的捷径。

`inv_growth_gap` 只有 305 家有值：同花顺、金山办公、指南针等 10 家
软件/互联网公司没有存货，科目不适用而非数据缺失——这也是
`n_peers` 取"保留指标最小同行数"（最弱环节口径）的原因：
计算机行业级 `n_peers` 因此是 305 而不是 315。

复核交叉校验告警时抓到一个真 bug：3 家 flagged（茅台 1.9%、
新大陆 4.1%、指南针 28.3%）**全是口径混用造成的误报**——
`/data` 概览列取营业总收入，报表侧却取营业收入，两者在有金融
业务的公司本就不同（指南针 21.46 亿 vs 15.39 亿）。已改为同口径
（`TOTAL_OPERATE_INCOME`）对比，重跑后告警清零、指标零漂移。

校准机制此前只有模拟 fixture 验证过。`scripts/build_fixture_from_raw.py`

被测公司用另一套"），然后同一份报表跑两次：

| 公司 | 全市场绝对线 | 食品饮料行业校准 |
|---|---|---|
| 伊利股份 | 0 项发现，风险分 0.0 [低] | **1 项重大**（资产负债率 61.51% > 行业 p75 46.83%），风险分 39.3 [高] |
| 青岛啤酒 | 1 项关注（应收剪刀差 23.5pct > 20pct），风险分 18.1 [中] | 0 项发现，风险分 0.0 [低] |

两个方向都出现了：行业线比绝对线**严**的时候能抓住被绝对线放过的杠杆风险，
**松**的时候能压制"在这个行业其实很 normal"的误报。

全行业扫描下来，111 家公司里有 **44 家**的触发项因校准而改变
（41 家变多、3 家变少），共 51 处单项判定翻转——绝大多数集中在
`debt_ratio`（绝对线 70% 对食品饮料普遍过松）和 `gross_margin_delta`
（绝对线 5pct 过松）。这不是说这些公司都有问题，而是说**换了参照系之后
"关注"的含义从"绝对偏高"变成了"处于同行业最差四分之一"**——后者需要读者
按前一种预期来读，否则会把 25% 的行业占比误读成"普遍恶化"。

#### 从 p75 单线升级为 p50~p90 区间判定

第一版校准只换了关注线（p75），重大线仍按 `abs_high / abs_warn` 的比例推导。
用真实数据一跑就发现这条比例线两个方向都错：

| 指标（食品饮料） | p75 | 比例重大线 | p90 | 比例线错在哪 |
|---|---|---|---|---|
| `ar_growth_gap` | 23.63 | 47.26 | 73.27 | 尾部极重，比例线把 16 家判成重大，实际最差十分之一只有 8 家 |
| `inv_growth_gap` | 21.53 | 43.06 | 35.34 | 分布紧凑，比例线放过行业尾部——最差十分之一只拿到"关注" |
| `gross_margin_delta` | 2.86 | 5.72 | 4.42 | 同上，5 家尾部公司被降级 |
| `debt_ratio` | 46.83 | 53.52 | 56.52 | 同上，4 家被降级 |

于是重大线改为直接取 p90（"行业最差十分之一，需要专项核查"），p90 缺失时才退回
比例推导。同一批 111 家公司重跑，**115 项校准发现里有 22 处判定翻转**，
两个方向几乎对称：

- **WARN→HIGH 共 11 处**（`inv_growth_gap` 5、`gross_margin_delta` 5、其他 1）：
  分布紧凑的指标上，比例线过松，行业尾部原本只拿"关注"。
- **HIGH→WARN 共 11 处**（`ar_growth_gap` 8、`debt_ratio` 4，减去重叠）：
  重尾指标上，比例线过严，把并非最差十分之一的公司升成了"重大"。

11:11 这个对称不是巧合——它说明比例线的问题不是"偏松"或"偏严"，
而是**它跟分布形状无关**。同一个 2 倍倍数，在紧凑分布上放过尾部、
在重尾分布上误伤中位，换行业就换个错法。

同时 detail 里现在给出整条区间，例如伊利股份的 `DEBT_RATIO`：

> 资产负债率 61.51%（观察线 47%；已按食品饮料行业分位校准（中位 35.1，p75 46.8，p90 56.5））

单说"超过 p75"会被读成"绝对偏高"——按定义任一行约 25% 的公司落在 p75 之上。
把中位数一起摆出来，读者才能自己定位"这家公司在行业区间的哪个位置"。
`evidence` 里同步增加 `line_high_source`（`industry:p90` 或 `industry:p75x2.00`）
与 `industry_p50` / `industry_p90` 两个机器可读字段，两条线各自可披露。

**这一升级的代价要记账**：`ar_growth_gap` 的 p90 对极值高度敏感——
食品饮料过滤后样本里兰州河（基期应收占营收 0.66%，按材料性门槛定义应当保留）
剪刀差 1733pct。去掉最大 1 个值，p90 从 73.27 掉到 64.90；去掉最大 3 个，掉到 52.77。
所以该行业该指标的重大线有约 ±20pct 的不确定带宽，`HIGH→WARN` 那 8 处翻转
有一部分是这个带宽造成的，不是干净的结构性结论。

## 关键设计决策

### 单条规则崩溃不能让整轮分析停摆

`RuleEngine.run()` 用 try/except 包住每条规则，失败就记一条 `ERR_<rule>` 然后继续。

在财务场景里，**"少报一个异常"比"整份报告没出来"更危险**。
一个规则的边界条件写错（比如除零）不应该让其余 8 条规则的结果一起消失。
测试 `test_broken_rule_does_not_break_engine` 用一条必抛异常的假规则钉住了这个行为。

### 未识别的行要记下来，不能静默丢弃

`ExtractAgent.parse_text()` 逐行正则匹配中文科目名，匹配不上的行全部记入
`meta["unrecognized"]`，CLI 会打印到 stderr 提醒人工核对。

静默丢弃是财务数据处理里最危险的行为——你不知道自己漏了什么。
宁可让使用者看到"有 12 行没认出来"，也不要给他一份看似完整实则残缺的报表。

顺带一个实测踩到的坑：初版正则写成"整行必须以数字结尾"，
结果真实报表（行末几乎都带"万元"）**一行都解析不出来**，
10 个科目全部落入未识别列表。这个 bug 单看代码不容易发现——
必须拿真实格式的行去跑。现在正则允许行末单位，并统一换算到万元口径
（亿元 ×10000、千元 ×0.1、元 ×0.0001）。
测试 `test_line_with_unit_suffix_is_parsed` 与 `test_unit_conversion_to_wan_yuan` 钉住了它。

### 研判章节不能是明细的复述

第一版 `ReportAgent.reason()` 在无 LLM 时就是：

```python
parts = [f"### {f.title}\n{f.detail}" for f in findings]
```

这导致报告的第三章和第四章内容完全一样——**篇幅上去了，信息量为零**。
在作品集里这会被一眼看穿。

改写成真正的跨发现聚合：用静态归属表把规则聚成"收入质量 / 资产质量 / 偿债能力"
三条主线索，每条给出共同成因推断和核查方向，再排出核查优先级。
测试 `test_reasoning_does_not_restate_details` 把"复述即失分"这条约束固化下来。

**这是零依赖模板的价值所在**：不是"没有 LLM 时的降级方案"，
而是"LLM 不该做的那部分"——聚合与归因是确定性的，交给模型反而不可靠。

### 勾稽校验为什么排在第一

`BS_IDENTITY` 是 `DEFAULT_RULES` 里的第一条。因为**如果报表本身不平，
后面所有比率分析都建立在错误数据上**。先验证数据可信，再分析数据含义——
这个顺序不能反。

### 持续性信号要升级原有发现，不能新增一条

用户对这个功能的需求原话是：

> 「连续三年应收增速超营收 20pct」比「今年突然超一次」更值得警惕

直觉上会想"那就再报一条持续性 Finding"。但这样做有两个后果：

1. **风险分双算**——同一个应收问题，单期一次 + 持续性一次，`risk_score` 会加两遍
2. **报告里同一问题出现两次**——读者会以为是两个独立问题，核查顺序也被打乱

所以实现是**在原 Finding 上提升一级严重度并追加说明**：

```python
f.level = _escalate(f.level)          # WARN → HIGH，HIGH 不越界
f.detail += "该信号在 2023A→2025A 连续 2 个报告期重复出现，非孤立波动，已升级为重大。"
f.confidence = min(1.0, f.confidence + 0.1)
```

配套的两个判定口径：

- **"连续"不是"累计"**：要求最近 N-1 个相邻期配对**全部**触发。中间中断一期不计——
  一次坏、一次好、一次坏不是趋势，是波动。
- **重大不越界**：`_escalate()` 到 HIGH 就停。持续性只能把"关注"提升到"重大"，
  不能造出一个更严重的档位——动作上无法区分。

测试 `test_escalates_when_signal_persists` / `test_interrupted_signal_does_not_escalate`
（中断一期不升级）/ `test_escalation_is_idempotent_on_level` 三条分别钉住这三个口径。

### 为什么趋势判定要求至少 3 期

两期只能算一次同比，任何"趋势"都无从谈起。`RuleBook.trend_min_periods = 3`
意味着：2 期输入时序列规则全部静默跳过，`escalate_persistent_findings` 也直接返回——
**退化成一个纯两期分析，行为与改造前完全一致。**

这不是"少了个功能"，是**边界条件必须显式**。传 2 期却试图做趋势判定，
只会得到"看起来做了其实没做"的假象。

注意这个门槛只管"跑不跑趋势规则"，不管"复发几次算持续"——后者是
`persistence_min_pairs`。两个参数分开之后，把持续性收紧到 3 对
（"连续三年"）不会再连带把 3 期数据的公司踢出趋势分析，
`test_stricter_persistence_does_not_raise_enable_gate` 钉住这条性质。

## 已知局限（诚实清单）

1. **报表科目靠正则解析**：格式一变就要改别名表。真实场景应接 XBRL 或财 reporting 系统导出。
2. **单位靠行末文本判断**：若报表在表头统一标注"单位：万元"而每行不带单位，
   当前会按"无单位即万元"处理——恰好对，但这属于巧合而非设计。需要在解析前显式传入表头单位。
3. **规则阈值未经历史回测**：观察线来自会计常识，不是从样本里拟合出来的。上线前必须校准。
4. **风险分权重是手工设定**：重大 10 / 关注 4 / 提示 1 的比值没有数据支撑。
   已做敏感性分析（`scripts/sensitivity.py`）：35 个组合里 24 个不翻档，
   默认参数在稳健区间内。但这只覆盖了已构造的 4 个场景，不等于全市场稳健。
5. **持续性判定默认只覆盖最近 2 个相邻配对**：`persistence_min_pairs = 2`
   即"最近两期都命中才算持续"，对应的是**连续两年**（两次同比）的持续性。
   原始需求里"连续三年应收增速超营收"这种更严的场景，把这个参数调到 3 即可
   （它已与 `trend_min_periods` 拆开，不会再连带抬高趋势启用门槛）。
6. **持续性升级只看单条规则的跨期命中**：不识别"两条不同规则轮流出现"的组合型持续信号
   （比如一期 `AR_GAP`、一期 `INV_GAP` 交替）。组合持续性是比单规则持续更弱的信号，
   但确实存在。
7. **`QUALITY_DRIFT` 的指标权重仍未经专家校准，但翻转规模已用真实数据量化**：
   5 项指标已按重要性加权（毛利率 3 > 净利率 2 = 经营现金流/净利润 2 >
   资产负债率 1 = 流动比率 1，门槛 5 分），解决了等权计数把
   "现金流+杠杆+流动性齐坏"与"毛利率+净利率齐坏"判成同一严重度的问题
   （见设计说明第十四节）。2026-10-16 对食品饮料等距抽样 30 家补抓
   2023AR 与三期现金流量表后重跑：**翻转 5 处（30 家的 17%）**，
   4 家新触发全部恰好 5 分（毛利率+净利率齐坏，含贵州茅台），
   1 家被抑制（桂发祥，净利率+杠杆+流动性 4 分——单期规则
   SWING_SCAN 仍以净利润 −190.6% 抓住）。四个方向全部符合设计预期。
   **仍未做**：用专家标注样本校准权重本身（当前是推理起点），
   以及茅台式"三年仅降 0.79pct 也触发"的幅度读法需要读报告的人知情。
8. **真实 LLM 验证只跑过一次，而且是本地 4B 模型**：2026-10-16 用本地 Ollama
   （qwen3:4b-instruct-2507-q4_K_M，temperature 0.1，每场景 3 次）跑通全链路：
   事实保真度 4/4 场景 100%（验收线达标）、覆盖率 100%、复述率 0%、
   可复算性 33%~67%。这次运行还抓出并修掉了覆盖率检查器的一个 bug——
   stub 照抄标题恒 100%，真实模型一改写措辞就恒 0%，**指标对它的主要用户群
   恒为 0，等于没有指标**（详见设计说明第十节）。**尚未用云端大模型跑过**：
   4B 的保真度达标不能外推，云端跑法是
   `FINAGENT_LLM_API=<端点> FINAGENT_LLM_MODEL=qwen-plus FINAGENT_LLM_KEY=<key>
   python scripts/ab_test.py --llm api --runs 3`。
   另外，真实模型在 temperature 0.1 下仍未做到逐字节确定（3 次运行可复算
   33%~67%）——这实证了"判定交给规则、措辞才交给 LLM"的架构主张。
9. **默认基准簿仍是模拟数据，真实数据要显式抓取**：`industry_benchmarks.json`
   是演示 fixture（测试钉住其具体数值，不能覆盖）；真实抓取产物在
   `industry_benchmarks.auditdog.json`，由 `scripts/fetch_benchmarks.py` 生成。
   真实数据自身的局限：来源是第三方站点的 **AI 抽取**结果而非审计数据；
   金额只有 3~5 位有效数字（"20.45 亿"）；站点入库不全（三一重工 600031 查不到），
   基准存在幸存者偏差；站点 `/data` 的行业公司数（食品饮料 122）与其 compare API 的
   `sample_size`（84）口径不一致，本工具取前者。此外只有 4 条规则支持校准，
   `OCF_DIVERGE`、`GOODWILL` 等仍是全市场固定线。
10. **p75 分位本身带约 5pct 的门槛不确定性**：增长类指标的材料性门槛定在
    "基期科目 < 基期营收 0.1%"，离线重算 0.5% / 1.0% 两档会让
    食品饮料 `ar_growth_gap` 的 p75 从 23.63 降到 18.04。没有为了数字好看
    抬高门槛（被排除的是山西汾酒基期 7.5 万这类近乎不存在的基数），
    但用阈值做判定时要承认这个带宽。**这个带宽同样是行业相关的**：
    电子行业 485 家在 0.1% / 0.5% 两档下都排除 0 家、分位数纹丝不动，
    抬到 1.0% 才排除 2 家（p90 29.73→28.19）——食品饮料那 5pct 抖动
    来自其小基数公司的密度，不是门槛定义本身有问题。
11. **校准会改变"关注"的含义，而不只是灵敏度**：以 p75 作观察线，
   按定义任一行约四分之一公司会落在线上。食品饮料实测 111 家里 44 家
   触发项因校准改变——读报告的人若仍按"绝对偏高"理解"关注"，
   会把行业常态误读成普遍恶化。
12. **重尾指标的 p90 不稳，且「不稳」有两个不同的量，别混用**：区间判定把
    重大线从拍倍数改成行业 p90，语义干净了，但 p90 本身在重尾分布上不稳。
    两种量化方式结论差一个数量级：

    **① 去极值法**（固定样本，删掉最大 k 个值看 p90 怎么变）——衡量
    "个别极端公司的影响"。食品饮料 `ar_growth_gap` 里兰州河（基期应收
    占营收 0.66%，按材料性门槛定义应当保留）剪刀差 1733pct：去掉最大 1 个
    值 p90 从 73.27 掉到 64.90，去 3 个掉到 52.77（−28%）；电子 485 家
    同操作只掉 4%／14%。

    **② bootstrap**（重抽样，看"换一批同行这条线会漂多少"）——衡量
    "这个基准本身有多可信"，更贴近实际使用场景：明年同行名单就会变。
    `.scratch/p90_sample_size.py` 三行业各 2000 轮实测的相对半宽
    （95% 区间半宽 ÷ p90 本身）：

    | 指标 | 食品饮料 n≈111 | 电子 n=485 | 计算机 n≈315 |
    |---|---|---|---|
    | `ar_growth_gap` | **73%** | 27% | 25% |
    | `inv_growth_gap` | 19% | 24% | 34% |
    | `debt_ratio` | **10%** | **6%** | **8%** |
    | `gross_margin_delta` | 22% | 15% | 34% |

    读法有两条：**`debt_ratio` 是唯一在三行业都可信的指标**（n≈100 就到
    10% 以内），与第七节"杠杆跨行业趋同"的发现互相印证——紧凑分布 +
    跨行业稳定 → 分位数可信。**`ar_growth_gap` 最不可信**：食品饮料
    p90=73.27 的 95% 区间是 [44, 146]，换一批同行能差一倍。而且 bootstrap
    半宽约按 1/√n 衰减，要把它压到 10% 需要约 3600 家同行（A 股全电子
    才 485 家）——**这个指标的重大线在当前样本量下永远达不到干净结论**，
    HIGH→WARN 的翻转不能当结构性结论用。同一 `gross_margin_delta` 在
    电子（15%）与计算机（34%）差一倍，说明**同为 n>300 的行业，分布形状
    决定可信度，不能只看样本数**。
13. **底稿的程序区是按执行动作反推的**：勾稽、分析、趋势三项程序由实际跑过的环节生成，
    但"追加函证""实地走访"这类需要人工触发的程序不会自动出现，
    底稿仍需要人工补程序、签编制人/复核人名。
14. **`NET_MARGIN_TURN` 只覆盖"过零轴"，不覆盖"亏损扩大"**：由盈转亏是
    定性变化，−3% → −6% 是幅度恶化，后者至今没人管。全样本 911 家里
    常年亏损且亏损扩大的公司数量尚未统计，所以没有贸然加规则——
    先把缺口量出来再定阈值，是这里一贯的顺序（本次转亏规则就是这么补的，
    见设计说明第十五节）。另外这条规则的重大线按**亏损深度 5%** 定而非降幅，
    意味着"从 30% 掉到 −1%"只判关注，虽然降幅 31pct——这是有意的：
    降幅会给高基数公司记一笔它并不严重的账。

**这个项目的价值不在代码，在于它证明了一件事**：

懂会计的人做 AI 应用，第一反应不是"用大模型分析财报"，
而是"**哪些环节必须确定性，模型只能在哪儿介入**"。

规则引擎判异常、LLM 写结论——这个分工不是为了保守，
是因为**一份不能被复算的财务分析报告，在专业场景里等于没有价值。**
